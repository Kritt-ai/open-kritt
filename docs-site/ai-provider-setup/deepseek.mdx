---
title: 'DeepSeek API checks'
description: 'Save a DeepSeek key, discover models, and check text API access from Accounts.'
---

DeepSeek is available in **Accounts** for model discovery and a short text API
check. It is not available for scan execution or draft generation, and no DeepSeek
scan harness is offered.

1. Open **Accounts → Show or hide providers** and select **DeepSeek**.
2. Obtain a key from the [DeepSeek platform](https://platform.deepseek.com/api_keys),
   then select **Add DeepSeek key** in Accounts.
3. Select **Load DeepSeek models** to retrieve the current authenticated model list.
4. Choose a model and select **Run text API check**. This sends the fixed message
   “Reply with OK.” and may incur a small API charge. The check reports success or
   a sanitized error.

Loading models and checking the API are explicit actions. Saving a key does not
contact DeepSeek. The check sends no repository content, user prompts, or tools.
An unavailable model must be reselected; the application never substitutes one.

## Credentials and protocol

Accounts uses the existing protected provider credential file and mirrors changes
to the project `.env` when that persistence path is configured. Keys are not returned
to the browser. A native backend can also read `DEEPSEEK_API_KEY` from its own process
environment; Compose users should add the key through Accounts.

The implementation uses Bearer authentication at the fixed
`https://api.deepseek.com` origin, `GET /models`, and non-streaming
`POST /chat/completions`. Redirects are rejected. Requests have a timeout and response
size limit. The diagnostic disables thinking and caps output at 32 tokens.

DeepSeek currently documents `deepseek-flash` and `deepseek-v4-pro`; the selector
uses the live model list rather than assuming those names remain available.
See the official [API introduction](https://api-docs.deepseek.com/),
[model listing](https://api-docs.deepseek.com/api/list-models/), and
[Chat Completions reference](https://api-docs.deepseek.com/api/create-chat-completion/).

DeepSeek also documents [Responses](https://api-docs.deepseek.com/guides/responses_api/)
and [Anthropic-compatible APIs](https://api-docs.deepseek.com/guides/anthropic_api/).
Compatibility is partial: Responses is stateless and ignores some parameters;
the Anthropic interface can map unsupported model names and ignores some fields.
Those protocols and coding harness integrations are not enabled by this feature.

## Visibility

New browser profiles show Codex and Claude Code. **Show or hide providers** in
Accounts or beside a provider selector lets you change that view. Preferences persist
in this browser and synchronize across its tabs. Hidden configured providers are
counted in the manager and can be shown again. Hiding never removes keys or accounts;
an existing selected provider remains visible in its selector.
