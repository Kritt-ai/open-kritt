title: 'DeepSeek'
description: 'Save a DeepSeek key, discover models, and run scans or draft generation through Codex.'
---

The **DeepSeek** provider uses `DEEPSEEK_API_KEY` and runs through the **Codex**
harness. It is available for scans, workflow and post-script drafts, model discovery,
and a short API check from Accounts.

1. Open **Accounts**. If DeepSeek is hidden, select it under **Show or hide providers**.
2. Obtain a key from the [DeepSeek platform](https://platform.deepseek.com/api_keys),
   then select **Add DeepSeek key** in Accounts.
3. Select **Load DeepSeek models** to retrieve the current authenticated model list.
4. Create or duplicate a scan, choose **DeepSeek**, then select one of the models from
   the live catalog. Codex is selected as the compatible harness.
5. Optionally choose a model in Accounts and select **Run text API check**. This sends the fixed message
   “Reply with OK.” and may incur a small API charge. The check reports success or
   a sanitized error.

Loading models and checking the API are explicit actions. Saving a key does not
contact DeepSeek. The diagnostic sends no repository content, user prompts, or tools.
Scans and draft generation send their configured prompts and relevant workspace content.
An unavailable model must be reselected; the application never substitutes one.

## Credentials and protocol

Accounts uses the existing protected provider credential file and mirrors changes
to the project `.env` when that persistence path is configured. Keys are not returned
to the browser. A native backend can also read `DEEPSEEK_API_KEY` from its own process
environment. Compose users can add the key through Accounts or `./kritt setup`.

The implementation uses Bearer authentication at the fixed
`https://api.deepseek.com` origin. The engine uses `GET /models` for the scan picker
and DeepSeek's Responses compatibility for Codex jobs. The Accounts diagnostic uses
non-streaming `POST /chat/completions`; it rejects redirects, applies a timeout and
response-size limit, disables thinking, and caps output at 32 tokens.

DeepSeek currently documents `deepseek-flash` and `deepseek-v4-pro`; the selector
uses the live model list rather than assuming those names remain available.
See the official [Codex integration guide](https://api-docs.deepseek.com/quick_start/agent_integrations/codex/),
[Responses guide](https://api-docs.deepseek.com/guides/responses_api/),
[API introduction](https://api-docs.deepseek.com/),
[model listing](https://api-docs.deepseek.com/api/list-models/), and
[Chat Completions reference](https://api-docs.deepseek.com/api/create-chat-completion/).

DeepSeek's Responses compatibility is stateless and ignores some parameters. The
engine therefore uses fresh, isolated Codex jobs and disables Codex's built-in web
search for this provider. Repository tools inside the disposable scan runner remain
available to the Codex agent.

## Visibility

New browser profiles show all providers, including DeepSeek in Accounts.
**Show or hide providers** in Accounts or beside a provider selector lets you change
that view. Existing preferences are preserved and synchronize across the browser's
tabs. Hidden configured providers are counted in the manager and can be shown again.
Hiding never removes keys or accounts; an existing selected provider remains visible
in its selector.
